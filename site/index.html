Start in 3 commands

Download, make it executable, run it. Replace <VPS-IP> with your VPS IP or hostname, and vps2 with any alias you like.

curl -O https://raw.githubusercontent.com/mymyanmarland/vps-connect/main/connect-vps.sh
chmod +x connect-vps.sh
./connect-vps.sh --name vps2 --host <VPS-IP>
ssh vps2

Tip: try the dry run first — it changes nothing: ./connect-vps.sh --dry-run --name vps2 --host <VPS-IP>

Step by step

1. Put the script on your terminal device.
On a PC, download it from the GitHub repo and open a terminal in that folder. On Android, use Termux and download it there. This chat app itself is not a terminal — the script runs in a real terminal app.
2. Run it.
./connect-vps.sh --name vps2 --host <VPS-IP> — or just ./connect-vps.sh and answer the two prompts: alias, then IP.
3. First time only: type the VPS password in your own terminal, at that prompt.
Characters will not show while you type — that is normal. Never send a password in chat, email, or a screenshot. The script never stores it.
4. Done. Connect any time.
ssh vps2 — for a new VPS, run the script again with a new name and IP. For a new device, run the script again on that device.

Safety, in plain words

  • Private key stays on your device. Only the .pub file is sent to a VPS.
  • Password is never stored by the script. Not in a file, not in an environment variable, not in a command.
  • Config is backed up to ~/.ssh/config.bak-<date>-<pid> before editing, and a second run with the same alias replaces that block — it never duplicates it.
  • Unsafe input is rejected before any SSH command runs: bad aliases, bad ports, and hosts with spaces or shell characters.
  • No automatic installs. If OpenSSH is missing, the script prints an install hint and exits.

FAQ

Is this a web panel?

No. There is no website to log into and no server to run. It is one script you run in your own terminal.

Does it work for any VPS?

Yes — any VPS that accepts SSH. Change only --name and --host per VPS.

Can I use it on more than one device?

Yes. Run the script once on each device. Each device gets its own key; the VPS accepts all of them.

What if the test fails?

Check the IP, user, and port, then run again with the same alias — the block will be replaced, not duplicated. If the password was not accepted on first copy, no config change was made yet.

What was tested?

Locally, with no real VPS contact: syntax, help, dry-run, temp-HOME runs (key reuse, backup, same-alias replacement, validation failures), and real ed25519 generation in a temp HOME. A real VPS copy and a real phone run are still for you to test on a VPS you choose.
